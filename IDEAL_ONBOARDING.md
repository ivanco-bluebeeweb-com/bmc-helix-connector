# BMC Helix Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: агент service
desk, ITSM-администратор, впервые открывающий приложение.

## 1. Credential type
AR REST host + username + password (JWT login flow) — единственный практичный способ
без завязки на конкретную SSO-конфигурацию тенанта.

## 2. Идеальный флоу (без ограничений SDK)
1. **Одна простая форма** — Host, Username, Password. Без переключателей режимов
   аутентификации (в отличие от ServiceNow, здесь только JWT-логин).
2. **Проверка через реальный запрос** — вызов `/api/jwt/login` перед сохранением токена,
   чтобы подтвердить host+username+password разом, а не сохранять вслепую.
3. **Понятная подсказка про формат хоста** — AR REST host обычно выглядит как
   `https://<tenant>-restapi.onbmc.com` (SaaS) или `https://<host>:<port>` (on-prem) —
   плейсхолдер должен показывать оба варианта, так как формат сильно отличается.
4. **Health snapshot сразу после подключения** — открытые инциденты по статусу, чтобы
   пользователь увидел живые данные сразу, а не пустой экран.
5. **Явное объяснение формата qualification-запросов** — при первом использовании
   фильтра по статусу/приоритету подсказать формат `'Status' = "New"` (AR System's own
   query syntax), так как он сильно отличается от привычного SQL/JQL и без объяснения
   пользователь не поймёт, почему его фильтр не работает.
6. **Понятные ошибки авторизации** — если JWT истёк, явно предложить переподключиться,
   а не показывать generic 401 — токены AR System живут ограниченное время и это
   ожидаемая, а не аварийная ситуация.
